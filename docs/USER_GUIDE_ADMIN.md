## 系统概述

IDC 数据中心综合布线项目管理系统是一套面向数据中心工程项目全生命周期管理的平台，覆盖项目立项、团队协作、进度填报与审核、文档归档、数据分析等核心业务环节。

系统由三端组成：

| 端 | 技术栈 | 访问方式 |
|----|--------|---------|
| **Web 端** | Vue3 + Element Plus | 浏览器访问 `http://服务器IP/` |
| **微信小程序** | uni-app | 微信搜索「IDC项目管家」 |
| **后端服务** | Spring Boot | 提供 RESTful API 与 WebSocket 服务 |

### 角色信息

| 项目 | 内容 |
|------|------|
| 角色名称 | 系统管理员 |
| 角色代码 | `admin` |
| 角色定位 | 拥有系统全部权限，可管理用户、角色、权限、配置及所有业务数据 |
| 默认账号 | `admin` / `admin123` |

> 🔒 出厂默认账号仅用于初次部署登录，**正式上线前请务必修改默认密码**。

## 一、角色定位与权限范围

### 1.1 职责定位

系统管理员是整个平台的最高权限持有者，主要承担以下职责：

- **账号与组织管理**：维护系统用户、角色、权限、岗位体系，保障组织架构与系统权限模型的一致性。
- **系统配置运维**：管理系统全局参数、缓存、健康状态，保障系统稳定运行。
- **业务数据兜底**：在项目经理或工程师缺位时，可对项目、文档、进度、客户等全量业务数据进行查询与维护操作。
- **权限审计与安全**：通过操作日志审计关键写操作，遵循最小权限原则为其他角色分配权限。

> 💡 管理员账号拥有系统全部权限，可绕过权限校验直接访问所有模块。请妥善保管账号，避免越权风险。

## 二、核心功能操作指南

本章重点说明管理员**特有**的系统管理类功能操作。项目、文档、进度、客户等业务功能的操作与项目经理/工程师一致，请参考通用《用户操作指南》。

### 2.1 用户管理

**操作路径**：Web 端 → 「系统管理」→「用户管理」

#### 2.1.1 新增用户

1. 进入用户管理页面，点击右上角「新增用户」按钮。
2. 在弹窗中填写用户信息：

| 字段 | 规则 | 是否必填 |
|------|------|---------|
| 用户名 | 3-20 位，仅字母、数字、下划线 | ✅ |
| 姓名 | 最多 50 字符 | ✅ |
| 密码 | 8-32 位，需同时含大小写字母、数字、特殊字符 | ✅ |
| 手机号 | 1 开头的 11 位手机号 | ❌ |
| 邮箱 | 合法邮箱格式 | ❌ |
| 岗位 | 从岗位下拉列表选择 | ❌ |
| 角色 | 分配系统角色（可多选） | ✅ |
| 状态 | 启用 / 停用 | ✅ |

3. 点击「保存」，系统提示「新增用户成功」。

> 💡 **批量导入**：点击「下载模板」获取 Excel 模板，填写后点击「批量导入」上传。导入结果会汇总显示成功/失败条数。

#### 2.1.2 编辑用户

1. 在用户列表中找到目标用户，点击「编辑」按钮。
2. 修改需要变更的字段（密码留空表示不修改）。
3. 点击「保存」。

#### 2.1.3 密码重置

**方式一（编辑页）**：编辑用户时，在密码字段填入新密码并保存。

**方式二（列表快捷操作）**：点击列表中的「重置密码」按钮，输入新密码确认。

> ⚠️ 密码重置操作会记录到操作日志，但**不会记录密码明文**（仅记录操作类型），以防止密码泄露。重置后请通过安全渠道将新密码告知用户，并提醒用户首次登录后修改密码。

#### 2.1.4 启用 / 禁用用户

1. 在用户列表中找到目标用户。
2. 点击状态列的开关，或点击「启用/禁用」按钮。
3. 确认操作。

**注意事项**：
- 禁用后该用户立即无法登录，已签发的 JWT token 将在下次请求时被拦截。
- 启用后用户可重新登录，无需重置密码。
- 建议对离职员工及时执行禁用而非删除，保留操作痕迹便于审计。

#### 2.1.5 分配角色

1. 编辑用户，在「角色」字段勾选需要分配的角色。
2. 保存后角色立即生效，用户下次请求时获取新权限。

### 2.2 角色管理

**操作路径**：Web 端 → 「系统管理」→「角色管理」

#### 2.2.1 新增角色

1. 点击「新增角色」按钮。
2. 填写角色信息：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 角色名称 | 显示名称，如「项目经理」 | ✅ |
| 角色编码 | 唯一标识，如 `pm`，建议小写字母 | ✅ |
| 描述 | 角色职责说明 | ❌ |
| 状态 | 启用 / 停用 | ✅ |

3. 点击「保存」。

#### 2.2.2 权限分配

1. 在角色列表中点击目标角色的「分配权限」按钮。
2. 系统弹出**权限树**，按模块分层展示所有权限项。
3. 勾选该角色需要的权限（支持全选某模块）。
4. 点击「保存」。

**注意事项**：
- 权限分配**即时生效**，关联该角色的所有用户下次请求即可使用新权限。
- 遵循**最小权限原则**：仅勾选完成工作所必需的权限，避免过度授权。
- `admin` 角色的权限不可通过此界面调整（管理员拥有全部权限，由系统内置）。

#### 2.2.3 分配用户

在角色列表中点击「分配用户」，可将用户加入或移出该角色。一个用户可同时拥有多个角色，权限取并集。

### 2.3 权限管理

**操作路径**：Web 端 → 「系统管理」→「权限管理」

#### 2.3.1 查看权限树

1. 进入权限管理页面，默认展示**权限树形结构**。
2. 权限按模块分组（项目管理、文档管理、进度任务、客户管理、系统管理、统计分析等）。
3. 支持切换为「平铺列表」视图，便于按编码检索。

> 💡 权限编码采用 `模块:资源:操作` 三段式命名，例如 `system:user:add` 表示系统模块下用户资源的新增操作。

#### 2.3.2 新增 / 编辑权限

1. 点击「新增权限」或在权限树中点击某节点「编辑」。
2. 填写权限信息：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 权限名称 | 显示名称 | ✅ |
| 权限编码 | 唯一标识，三段式命名 | ✅ |
| 上级权限 | 选择父节点（用于构建权限树） | ❌ |
| 权限类型 | 菜单 / 按钮 / 接口 | ✅ |
| 描述 | 补充说明 | ❌ |

3. 点击「保存」。

**注意事项**：
- 新增的权限项需在「角色管理」中分配给对应角色后才会对用户生效。
- 权限编码一旦创建**不建议修改**，因为后端接口通过 `@RequiresPermission("编码")` 注解硬编码引用。
- 删除权限项前请确认无角色引用，否则可能导致权限校验异常。

### 2.4 岗位管理

**操作路径**：Web 端 → 「系统管理」→「岗位管理」

#### 2.4.1 新增岗位

1. 点击「新增岗位」按钮。
2. 填写岗位信息：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 岗位名称 | 如「施工工程师」 | ✅ |
| 岗位编码 | 唯一标识 | ✅ |
| 岗位级别 | 数字，用于职级比较 | ✅ |
| 描述 | 岗位职责说明 | ❌ |
| 状态 | 启用 / 停用 | ✅ |

3. 点击「保存」。

#### 2.4.2 编辑 / 删除岗位

- **编辑**：点击列表「编辑」按钮，修改后保存。
- **删除**：点击「删除」按钮，确认后删除。

**注意事项**：
- 岗位级别用于权限校验时的**职级比较**，例如项目经理可审核工程师的进度填报。
- 删除岗位前请确认无在用用户关联该岗位，建议先将其关联用户改为其他岗位，再删除。
- 停用岗位后，已关联该岗位的用户不受影响，但新建用户时无法再选择该岗位。

### 2.5 系统配置

#### 2.5.1 系统参数配置

**操作路径**：Web 端 → 「系统设置」→「系统配置」

| 配置项 | 说明 |
|--------|------|
| 系统名称 | 显示在浏览器标题和登录页的系统名称 |
| 系统Logo | 系统标志图片 |
| 文件上传限制 | 单文件最大上传大小 |
| 会话超时 | 登录会话超时时间（分钟） |
| 缓存过期时间 | Redis 缓存默认过期时间 |

**操作步骤**：
1. 修改需要调整的配置项。
2. 点击「保存设置」按钮。
3. 配置即时生效，部分配置可能需要刷新页面。

> ⚠️ 系统配置变更将持久化到数据库，影响所有用户，请谨慎操作。修改前建议记录原值以便回滚。

#### 2.5.2 缓存管理

**操作路径**：后端接口 `/cache/*`（需 `system:cache:manage` 权限）

管理员可对 Redis 缓存进行读写删操作，用于运维场景下的缓存验证与清理。

**注意事项**：
- 仅允许操作 `cache:test:` 与 `cache:debug:` 前缀的测试缓存键。
- 系统对受保护前缀进行了硬编码限制，**禁止操作**以下缓存键：
  - `hbsz:jwt:blacklist:*`（JWT 黑名单）
  - `hbsz:login:fail:*`（登录失败计数）
  - `hbsz:login:lock:*`（登录锁定）
  - `hbsz:user:perms:*`（用户权限缓存）
  - `hbsz:user:roles:*`（用户角色缓存）
  - `hbsz:captcha:*`（验证码）
  - `hbsz:idempotent:*`（幂等令牌）
- 触碰受保护键会被直接拒绝并抛出业务异常。

### 2.6 工作量管理（v1.1 新增）

v1.1 版本新增工作量管理机制，通过「计划工作量 / 已完成工作量 / 完成率」三维数据实现任务工作量的精细化管控。系统管理员作为全局数据兜底角色，可查看全量项目的工作量统计与风险看板工作量偏差预警。

#### 2.6.1 工作量统计卡片（工作台）

**操作路径**：Web 端 → 工作台（首页）

工作台新增**工作量统计卡片**（仅 admin / PM 可见），汇总展示管理员可见范围内的全部项目工作量数据：

| 指标 | 说明 |
|------|------|
| 计划工作量总计 | 所有进行中任务 plannedWorkload 之和（按工作量单位汇总） |
| 已完成工作量总计 | 所有任务 actualWorkload 之和 |
| 剩余工作量 | 计划工作量总计 − 已完成工作量总计 |
| 工作量完成率 | 已完成工作量 / 计划工作量，以进度条形式直观展示 |

> 💡 管理员拥有全部数据权限，卡片汇总范围为**全系统所有项目**；项目经理仅汇总其管理项目范围。

#### 2.6.2 风险看板工作量偏差预警

**操作路径**：Web 端 → 进度任务 → 风险预警看板

风险看板在原有「逾期任务 / 即将到期任务」分区基础上，新增**工作量偏差预警**：

- **判定规则**：当任务满足「实际完成工作量 < 计划工作量 × 80%」且任务状态非「已完成」时，自动标记为**偏差任务**并纳入风险等级计算。
- **偏差任务列表**展示：任务名称、所属项目、计划工作量、已完成工作量、完成率、偏差率。
  - 完成率 = 已完成工作量 / 计划工作量
  - 偏差率 = 1 − 完成率
- 偏差任务将提升任务的风险等级，便于管理员与 PM 重点关注。

> ⚠️ 工作量偏差预警依赖 PM 在创建/编辑任务时设定的「计划工作量」基准。若任务未设定计划工作量，则不参与偏差检测。

#### 2.6.3 日报导出工作量统计

**操作路径**：Web 端 → 数据分析 → 日报导出

日报导出 Excel 在原任务列表基础上新增 3 列：

| 新增列 | 说明 |
|--------|------|
| 计划工作量 | 任务设定的 plannedWorkload |
| 已完成工作量 | 任务累计的 actualWorkload |
| 工作量完成率(%) | 已完成 / 计划 × 100% |

前端日报页面的任务进度表格同步新增对应列，便于在线预览核对。

> 💡 管理员可导出全量项目日报；项目经理仅可导出其管理项目范围内的日报。

## 三、常见任务流程图解

### 3.1 新员工入职流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  1.创建用户  │ -> │ 2.分配角色   │ -> │ 3.分配岗位   │ -> │ 4.分配项目   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       │                  │                  │                  │
       ▼                  ▼                  ▼                  ▼
  系统管理→用户管理   编辑用户→勾选角色   编辑用户→选择岗位   项目协作→项目组管理
  填写基本信息       (如 engineer)       (如 施工工程师)     将用户加入项目组
  设置初始密码
```

**详细步骤**：
1. **创建用户**：「系统管理」→「用户管理」→「新增用户」，填写用户名、姓名、初始密码。
2. **分配角色**：在新增用户表单的「角色」字段勾选对应角色（如 `engineer`）。
3. **分配岗位**：在「岗位」字段下拉选择对应岗位（如「施工工程师」）。
4. **分配项目**：「项目协作」→「项目组管理」→选择目标项目→「添加成员」→选择刚创建的用户。
5. **通知用户**：将用户名、初始密码、系统访问地址通过安全渠道告知用户，提醒首次登录后修改密码。

### 3.2 权限调整流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ 1.编辑角色   │ -> │ 2.调整权限   │ -> │ 3.用户生效   │
└─────────────┘    └─────────────┘    └─────────────┘
       │                  │                  │
       ▼                  ▼                  ▼
  系统管理→角色管理   点击「分配权限」     关联用户下次请求
  点击「编辑」        勾选/取消权限项      自动获取新权限
```

**详细步骤**：
1. **编辑角色**：「系统管理」→「角色管理」→找到目标角色→点击「编辑」或「分配权限」。
2. **调整权限**：在权限树中勾选新增权限、取消不需要的权限，点击「保存」。
3. **用户生效**：权限**即时生效**，关联该角色的所有用户在下一次 API 请求时自动获取新权限，无需重新登录。
   > 如个别用户权限未刷新，可让其重新登录触发权限缓存重建。

### 3.3 系统初始化流程

适用于全新部署后的首次配置：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ 1.创建岗位   │ -> │ 2.创建角色   │ -> │ 3.创建用户   │ -> │ 4.配置系统参数│
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       │                  │                  │                  │
       ▼                  ▼                  ▼                  ▼
  系统管理→岗位管理   系统管理→角色管理   系统管理→用户管理   系统设置→系统配置
  创建项目经理/       创建 pm/engineer    创建各岗位用户      设置系统名称/Logo/
  工程师等岗位        等角色并分配权限    并分配角色与岗位    会话超时等参数
```

**详细步骤**：
1. **创建岗位**：先创建组织内所有岗位（项目经理、施工工程师、实施工程师等），设置岗位级别。
2. **创建角色**：创建对应角色（`pm`、`engineer`），并在权限树中为每个角色分配所需权限。
3. **创建用户**：为每位员工创建用户账号，分配角色与岗位。
4. **配置系统参数**：设置系统名称、Logo、文件上传限制、会话超时等全局参数。
5. **验证**：使用各角色账号登录，确认菜单与权限符合预期。

## 四、注意事项与限制条件

### 4.1 管理员账号安全

- **定期修改密码**：建议每 90 天修改一次管理员密码，密码需符合 8-32 位且含大小写字母、数字、特殊字符的复杂度要求。
- **不外传账号**：管理员账号仅限授权运维人员使用，禁止多人共享。如需多人协作，请为每人创建独立账号并分配 `admin` 角色。
- **修改默认密码**：系统出厂默认账号为 `admin / admin123`，**正式上线前必须修改**。
- **登录失败锁定**：连续登录失败会触发账号临时锁定，锁定期间无法登录。
- **退出登录**：离开工位时务必退出登录，避免会话被他人利用。

### 4.2 删除操作的级联影响

> ⚠️ 删除操作不可恢复，执行前请务必确认。

| 删除对象 | 级联影响 | 建议 |
|---------|---------|------|
| **用户** | 该用户作为项目经理的项目需先转移；项目授权、转移日志中关联该用户的记录会级联删除 | 优先选择「禁用」而非「删除」 |
| **项目** | 数据库外键 `ON DELETE CASCADE` 自动清理：项目授权、转移日志、任务、进度日志、文档、项目组成员等全部关联数据 | 删除前确认项目已归档或确无保留价值 |
| **任务** | `ON DELETE CASCADE` 自动清理任务进度日志 | 删除前可导出任务记录备查 |
| **角色** | 解除该角色与所有用户的关联、与所有权限的关联 | 删除前先确认无在用用户 |
| **岗位** | 解除该岗位与用户的关联 | 删除前先将关联用户改为其他岗位 |
| **权限项** | 解除该权限与所有角色的关联 | 删除前确认后端无 `@RequiresPermission` 引用 |

### 4.3 权限分配原则

- **最小权限原则**：仅为角色分配完成工作所必需的权限，避免过度授权。
- **职责分离**：关键操作（如进度填报与进度审核）应分配给不同角色，避免单点权限滥用。
- **定期审计**：定期检查各角色权限范围，清理冗余权限。可通过操作日志审计敏感操作。
- **权限编码不可随意改动**：后端接口通过 `@RequiresPermission("编码")` 注解硬编码引用权限编码，修改编码会导致权限校验失效。

### 4.4 系统配置修改

- **修改前记录原值**：系统配置变更影响所有用户，修改前建议记录原值以便回滚。
- **避免业务高峰期修改**：会话超时、缓存过期等参数调整可能影响在线用户，建议在低峰期操作。
- **缓存清理谨慎**：通过缓存管理接口操作 Redis 时，仅允许操作 `cache:test:` / `cache:debug:` 前缀键，受保护前缀（JWT、权限、验证码等）禁止触碰。

### 4.5 数据库外键策略说明

系统数据库外键采用以下策略：

| 策略 | 含义 | 适用场景 |
|------|------|---------|
| **CASCADE** | 父记录删除时，自动级联删除子记录 | 项目→项目授权、项目→转移日志、项目→任务、任务→进度日志、用户→项目授权、用户→转移日志 |
| **SET NULL** | 父记录删除时，子记录外键字段置空 | 部分可空的外键关联（如项目的客户字段） |
| **NO ACTION / RESTRICT** | 存在子记录时禁止删除父记录 | 防止误删导致数据孤立 |

> 💡 项目与任务的删除均依赖 `ON DELETE CASCADE` 自动清理关联数据，管理员执行删除操作前应充分评估级联影响。

## 五、问题排查与支持渠道

### 5.1 常见问题 FAQ

#### Q1：用户登录失败，提示「用户名或密码错误」

**排查步骤**：
1. 确认用户名、密码输入正确，注意大小写。
2. 检查用户状态是否为「启用」（在「用户管理」中查看）。
3. 检查是否因连续登录失败被锁定（锁定时间通常为 5-15 分钟，过后自动解锁）。
4. 如仍无法登录，管理员可在「用户管理」中重置该用户密码。

#### Q2：用户权限不生效，菜单或按钮缺失

**排查步骤**：
1. 确认用户已分配正确角色（「用户管理」→编辑用户→查看角色）。
2. 确认角色已分配对应权限（「角色管理」→分配权限→查看权限树勾选状态）。
3. 让用户**重新登录**，触发权限缓存重建（权限缓存存储在 Redis 的 `hbsz:user:perms:*` 键）。
4. 如仍不生效，联系运维检查 Redis 服务是否正常。

#### Q3：数据不显示或列表为空

**排查步骤**：
1. 检查筛选条件是否过严，尝试清除筛选条件后查询。
2. 确认用户是否有对应模块的查询权限（如 `project:query`）。
3. 检查该数据是否属于用户授权范围内（普通用户仅能查看授权项目）。
4. 管理员拥有全部权限，可绕过授权范围查看所有数据；如管理员也看不到，检查数据是否被归档或删除。
5. 打开浏览器开发者工具（F12）查看接口响应是否有异常。

#### Q4：操作日志在哪里查看

系统通过 `@OperationLog` 注解自动记录关键写操作（新增、修改、删除、密码重置、状态变更、角色分配、权限分配等），日志持久化到 `sys_operation_log` 表。日志字段包含：模块、业务类型、请求 URL、操作人、操作参数、操作结果、错误信息、操作时间。

> 注：密码重置类操作为防止密码泄露，**不记录请求参数**。

#### Q5：批量导入用户失败

1. 确认使用的是系统提供的最新模板（「用户管理」→「下载模板」）。
2. 检查 Excel 中用户名是否重复、密码是否符合复杂度要求、手机号/邮箱格式是否正确。
3. 导入结果会返回成功条数、失败条数及失败原因，根据失败原因逐条修正后重新导入。

### 5.2 日志查看方法

| 日志类型 | 位置 | 说明 |
|---------|------|------|
| 操作日志 | 数据库表 `sys_operation_log` | 记录用户关键写操作，可通过 SQL 查询 |
| 应用日志 | 后端服务器日志目录（如 `logs/`） | Spring Boot 运行日志，含异常堆栈 |
| 前端监控日志 | 后端 `/monitor/error` 端点接收 | 前端 JS 错误、Vue 组件错误等上报 |

**操作日志查询示例**：
```sql
SELECT * FROM sys_operation_log
WHERE module = '用户管理'
  AND create_time >= '2026-07-01'
ORDER BY create_time DESC;
```

### 5.3 系统健康检查

系统提供健康检查端点，可用于部署验证与监控：

- **业务健康检查**：`GET /system/health`
  返回 `status=UP` 与时间戳，用于存活探测。
- **系统信息查询**：`GET /system/info`
  返回系统名称、版本号、Java 版本、操作系统名称。
- **Spring Boot Actuator**：`GET /api/actuator/health`
  Spring Boot 标准健康检查端点，返回数据库、Redis 等组件健康状态。

> 💡 健康检查端点可用于负载均衡健康探测、容器编排存活探针等场景。
