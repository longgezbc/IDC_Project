# 01 - 项目总览与架构

> **项目名称**：IDC 数据中心综合布线项目管理系统（Hbsz IDC System）
> **文档版本**：v4.0（2026-08-23，基于最新代码库生成，本套 Wiki 为项目唯一的 Code Wiki）

---

## 1. 项目简介

本项目是面向 **IDC 数据中心综合布线工程** 的企业级项目管理系统，覆盖从项目立项、任务分解、进度填报与审核、工作量填报与考核、文档管理、项目授权与转移到归档的 **全生命周期管理**。

系统采用 **一套后端 API 服务 + 三个客户端** 的多端架构：

| 端 | 目录 | 技术栈 | 主要用户 |
|----|------|--------|----------|
| 后端 API | `Hbsz_IDC_System_end/` | Java 17 + Spring Boot 3 + MyBatis-Plus + MySQL + Redis | - |
| Web 管理端 | `Hbsz_IDC_System/` | Vue 3 + Element Plus + Vite + Pinia | 管理员、项目经理（PC 场景） |
| Android App | `Hbsz_app_Android/` | Kotlin + Jetpack Compose + Hilt + Retrofit | 项目经理、工程师（移动场景） |
| 微信小程序 | `hbsz_-uniapp_-vue-master/` | uni-app (Vue 3) | 现场工程师（轻量移动场景） |

## 3. 整体架构

```
                        +---------------------+
                        |    用户 / 浏览器     |
                        +----------+----------+
                                   |
              +--------------------+--------------------+
              |                    |                    |
      +-------v-------+   +-------v-------+   +--------v--------+
      |  Web 管理端    |   |  Android App  |   |  微信小程序       |
      |  Vue3+EP      |   |  Compose      |   |  uni-app         |
      |  (Nginx:8080) |   |  (Retrofit)   |   |  (HTTPS 域名)     |
      +-------+-------+   +-------+-------+   +--------+--------+
              |                    |                    |
              |  /api/* (HTTP)     |  /api/* (HTTP)     |  /api/* (HTTPS)
              |  /ws/*  (STOMP)    | (App v1.0.1 起     |
              +--------+-----------+--走 nginx:80 反代)--+
                       |                     |
              +--------v---------------------v--------+
              |        Nginx 反向代理 (frontend 容器)  |
              |  宿主机 80 -> 容器 8080（唯一公网入口）  |
              |  ^~ /api/  -> backend:8080            |
              |  ^~ /ws/   -> backend:8080 (Upgrade)  |
              |  ^~ /downloads/ -> 静态（APK 自更新） |
              |  /        -> try_files index.html     |
              +--------------------+------------------+
                                   |
              +--------------------v------------------+
              |       后端 API (backend 容器)           |
              |  Spring Boot 3, context-path=/api      |
              |  宿主机端口仅绑 127.0.0.1:8080          |
              |  （不对公网暴露，外部一律走 Nginx）        |
              |  JwtAuthInterceptor -> Controller     |
              |  -> @RequiresPermission 切面           |
              |  -> Service -> Mapper(MyBatis-Plus)    |
              |  Flyway 启动自动迁移 / WebSocket / 定时任务 |
              +-------+-----------------+-------------+
                      |                 |
              +-------v------+   +------v-------+
              |  MySQL 8.0   |   |  Redis 7.2   |
              |  (数据持久化)  |   |  (缓存/锁)   |
              +--------------+   +--------------+
```

### 3.1 请求处理链路（后端）

1. `ApiVersionFilter`：接口版本控制（当前 v1）
2. `XssFilter`：XSS 过滤
3. `JwtAuthInterceptor`：JWT 校验（放行 OPTIONS、`/system/config`、验证码等公开端点）、token 黑名单与过期校验，通过后写入 `UserContext`（ThreadLocal）
4. `PermissionAspect`（`@RequiresPermission`）：RBAC 权限校验，支持 AND/OR 组合与岗位职级限制
5. `RateLimitAspect` / `IdempotentAspect` / `OperationLogAspect`：限流、幂等、操作审计
6. `Controller -> Service -> Mapper`：标准三层
7. `GlobalExceptionHandler`：统一异常转 `Result<T>` 响应（code/message/data，字段驼峰）

### 3.2 实时通信

- 后端 `WebSocketConfig` 注册 STOMP 端点 `/ws`（SockJS），`JwtHandshakeInterceptor` + `AuthenticatedHandshakeHandler` 完成握手鉴权
- `NotificationPushService` 向指定用户推送站内通知
- Web 端通过 `@stomp/stompjs + sockjs-client`（`utils/websocket.js`），小程序通过 `utils/ws.js` 接入

### 3.3 App 自更新分发

- App 版本清单 `app-latest.json` 与 APK 均置于 `dist/downloads/`，由前端容器 nginx 作为静态资源提供（**dist 随前端镜像一同构建打入，自包含部署**）
- 客户端 `GET {host}/downloads/app-latest.json` 拉取清单 → 比对 versionCode → 下载 APK → 系统安装器

## 5. 关键设计决策与约束

以下约束来自项目实践沉淀，改动前必须评估影响：

- **API 响应字段统一 camelCase**；文件大小等展示类字段由后端格式化（如 `1.5MB`）直接下发
- **数据库变更一律走 Flyway**：`db/migration/V{YYYYMMDD}[_n]__{description}.sql`，脚本必须幂等（information_schema 存在性检查 + PREPARE/EXECUTE），禁止 `USE` 语句；后端启动时自动执行迁移，**部署新版本前必须先跑迁移**（实际由启动流程保证）
- **登录强制验证码**：`LoginDTO.captchaId + captcha`（`@NotBlank`）；验证码校验失败**不计入**账号锁定计数（防 DoS 锁号）
- **JWT**：access token 30 分钟，refresh token 7 天；`/system/config` 与验证码端点不拦截；解析校验 issuer/audience 防跨服务误用
- **进度填报必须上传施工图片**，且进度日志须经项目经理审核通过后才回写任务进度
- **工作量填报**只能选项目组成员（前后端双重校验），提交后进入待审核态，审核需 `workload:review` 权限
- **文件上传安全**：扩展名白名单 + magic number 校验（OOXML 的 `PK\x03\x04` 覆盖 docx/xlsx/pptx）；SVG 的 content-type 故意不映射，强制下载防 XSS
- **Redis 禁用 KEYS，必须 SCAN**；缓存管理接口需 `system:cache:manage` 权限
- **Nginx**：`/api/` 必须用 `^~` 前缀匹配（防静态规则截获带扩展名的 API 路径）；`/ws` 需 WebSocket 头；前端 history 路由用 `try_files`
- **端口安全**：后端容器宿主机端口必须绑定 `127.0.0.1:8080`（不公网暴露）；所有外部客户端（含 App）一律走 nginx 80 端口反代；App v1.0.1 起已将 `API_BASE_URL` 切换至 nginx（`http://124.220.158.177/api/`）
- **前端构建**：sourcemap 必须关闭、资源 hash 文件名、`import * as echarts from 'echarts'` 全量引入（渐变色需要）
- **Web 界面禁用 emoji 图标**，保持专业视觉语境
- **小程序 tabBar 仅支持 PNG/JPG**，生产 `urlCheck: true` 且 API 域名必须 HTTPS
- **前端图标按需注册**（[utils/icons.js](file:///c:/Users/QianLong/Desktop/Hbsz/Hbsz_IDC_System/src/utils/icons.js)）：`@element-plus/icons-vue` 不提供指纹图标，自定义 [FingerprintIcon.vue](file:///c:/Users/QianLong/Desktop/Hbsz/Hbsz_IDC_System/src/components/FingerprintIcon.vue) SVG 组件注册为全局 `Fingerprint`。**⚠ 白屏事故教训（2026-08-23）**：移除图标时，import 块与下方 `icons` 数组两处必须同步清理——若只在 import 中删除而保留数组里的裸标识符，Rollup 会把它当全局变量（构建通过！），运行时 ReferenceError 致整站白屏。维护口诀：「图标增删，import 与数组两处同步」
- **App 自更新分发**：`dist/downloads/`（APK + `app-latest.json`）随前端镜像一同 COPY 打入；改清单/换 APK 后必须 `docker compose up -d --build frontend`，仅 restart 不生效
