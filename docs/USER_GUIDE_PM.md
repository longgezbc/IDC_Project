## 系统概述

本系统为 IDC 数据中心综合布线项目管理平台，采用三端架构：

| 端 | 技术栈 | 访问方式 |
|----|--------|---------|
| **Web 端** | Vue3 + Element Plus | 浏览器访问 `http://服务器IP/` |
| **微信小程序** | uni-app | 微信搜索「IDC项目管家」 |
| **后端服务** | Spring Boot | 通过 Web 端 / 小程序端调用 |

> 💡 推荐使用 Chrome 90+、Edge 90+ 浏览器访问 Web 端，分辨率 1366×768 及以上。

## 一、角色定位与权限范围

### 1.1 角色定位

**项目经理（project_manager）** 是项目管理的第一责任人，负责项目从立项、团队组建、任务派发、进度审核到归档的全流程管控，同时承担授权审批、风险处置、客户维护及数据导出等职责。

核心职责：

- 统筹项目全生命周期管理，保障项目按期交付
- 审核工程师提交的进度填报，确保数据真实有效
- 监控逾期与即将到期任务，及时处置风险
- 审批工程师的项目授权申请，管控项目可见范围
- 导出项目日报，为决策提供数据支撑

### 1.2 权限范围矩阵

| 功能模块 | 查询 | 新增 | 编辑 | 删除 | 其他关键操作 |

| **项目管理** | ✅ | ✅ | ✅ | ✅ | 归档、授权转移 |
| **项目协作 — 授权申请** | ✅ | ✅ | — | — | 发起申请 |

| **文档管理** | ✅ | ✅ | ✅ | ✅ | 上传、下载 |

### 1.3 不可访问的功能

> ⚠️ 以下功能属于**系统管理**范畴，项目经理**无权访问**：

- 用户管理（新增/编辑/停用用户、批量导入、重置密码）
- 角色管理（角色创建、权限分配）
- 权限管理（菜单权限、按钮权限配置）
- 岗位管理（岗位 CRUD）

如需调整上述配置，请联系**系统管理员**处理。

## 二、核心功能操作指南

### 2.1 项目创建与管理

**操作路径**：`Web 端 → 项目管理 → 项目列表 → 新建项目`

**操作步骤**：

1. 进入「项目管理 → 项目列表」页面。
2. 点击右上角「新建项目」按钮，打开项目编辑表单。
3. **填写基本信息**：项目名称、项目编号、客户（下拉选择）、项目类型、起止日期、项目描述。
4. **分配团队**：在「项目团队」区域点击「添加成员」，选择工程师并指定角色（如组长/组员）。
5. **设置可见范围**：选择项目可见性：
   - `assignment`：仅被授权的工程师可见
   - `team`：项目组成员可见
   - `public`：全员可见
6. 点击「保存」完成创建，系统自动跳转至项目详情页。

**注意事项**：

- 项目编号建议遵循统一命名规范（如 `IDC-年份-序号`），便于检索。
- 团队成员必须为系统中已存在的工程师账号。
- 可见范围一经设置，后续可在项目详情页修改，但已生成的授权记录不会自动失效。

### 2.2 进度审核流程（重点）

**操作路径**：`Web 端 → 进度任务 → 进度审核` 或 `小程序 → 审核`

**操作步骤**：

1. 进入「进度任务 → 进度审核」页面，查看**待审核列表**。
2. 列表展示：任务名称、所属项目、填报工程师、填报时间、工作量、状态。
3. 点击某条记录进入审核详情页，**必须查看**：
   - 施工图片（点击可放大查看）
   - 工作量描述（已完成工作量、剩余工作量）
   - 填报时间与备注
4. 审核决策：
   - **通过**：点击「审批通过」按钮，可填写审核意见（选填），任务进度自动更新。
   - **驳回**：点击「驳回」按钮，**必须填写驳回意见**，工程师收到通知后重新填报。
5. 审核结果通过站内通知与小程序消息推送给工程师。

**注意事项**：

- ⚠️ **必须查看施工图片和工作量描述后才能通过审核**，禁止未核实即通过。
- 驳回必须填写明确意见，便于工程师整改。
- 一条填报记录只能审核一次，通过/驳回后不可撤销。

### 2.3 风险预警看板

**操作路径**：`Web 端 → 进度任务 → 风险预警看板` 或 `小程序 → 风险预警`

**操作步骤**：

1. 进入「风险预警看板」，看板按风险等级分区展示：
   - 🔴 **逾期任务**：计划完成日期已过但未完成
   - 🟡 **即将到期任务**：剩余天数 ≤ 阈值（默认 3 天）
2. 点击任务卡片查看详情，包含：任务名称、所属项目、负责人、计划日期、当前进度。
3. **处理风险**：
   - 联系任务负责人跟进（可点击「发送通知」提醒）。
   - 必要时调整任务计划日期或重新分配负责人。
   - 在任务详情页填写风险处理备注。
4. 任务状态变更后，看板自动刷新。

**注意事项**：

- 看板数据每 5 分钟自动刷新一次，也可手动点击「刷新」按钮。
- 逾期任务需优先处理，避免影响项目整体进度。

### 2.4 项目授权管理

**操作路径**：`Web 端 → 项目协作 → 项目授权管理` 或 `小程序 → 项目授权`

**操作步骤**：

1. 进入「项目授权管理」页面，切换到**待审批**标签。
2. 查看工程师提交的授权申请：申请人、目标项目、申请理由、申请时间。
3. 点击申请记录进入审批详情：
   - **授权（通过）**：确认授权范围后点击「授权」按钮，工程师即刻获得该项目查看权限。
   - **拒绝（驳回）**：填写拒绝理由后点击「拒绝」，工程师收到通知。
4. 已审批记录可在「已处理」标签中查询。

**注意事项**：

- ⚠️ **同一项目不可重复授权给同一工程师**，系统会自动校验并提示。
- 授权生效后，工程师可在其项目列表中查看该项目。
- 如需撤销授权，请联系系统管理员处理。

### 2.5 项目组管理

**操作路径**：`Web 端 → 项目协作 → 项目组管理`

**操作步骤**：

1. 进入「项目组管理」页面，点击「新建项目组」。
2. 填写项目组名称、关联项目、描述。
3. **添加成员**：点击「添加成员」，从工程师列表中选择一名或多名的工程师加入项目组。
4. **指定组长**：在成员列表中，点击某成员后的「设为组长」按钮，组长拥有该组任务的派发权限。
5. 点击「保存」完成创建。

**注意事项**：

- 一个项目组必须有且仅有一名组长。
- 项目组成员可同时属于多个项目组。
- 删除项目组不会删除关联项目，但会解除成员关联。

### 2.6 日报导出

**操作路径**：`Web 端 → 数据分析 → 日报导出`

**操作步骤**：

1. 进入「日报导出」页面。
2. **选择日期范围**：设置开始日期与结束日期（最长 31 天）。
3. **选择项目**：可勾选一个或多个项目（不选则导出所有有数据的项目）。
4. 点击「导出 Excel」按钮，系统生成 `.xlsx` 文件。
5. 浏览器自动触发下载，或在「导出记录」中查看历史并重新下载。

**注意事项**：

- 📊 **导出的 Excel 每个项目一个 Sheet**，包含任务列表、进度、工作量等。
- 日期范围超过 31 天时系统会提示限制。
- 导出任务异步执行，大数据量时请耐心等待或从「导出记录」下载。

### 2.7 客户管理

**操作路径**：`Web 端 → 客户管理 → 客户列表` 或 `小程序 → 客户管理`

**操作步骤**：

1. 进入「客户管理」页面，可按客户名称、联系人、状态进行搜索。
2. **新增客户**：点击「新增」按钮，填写客户名称、联系人、联系电话、邮箱、地址、备注，点击「保存」。
3. **编辑客户**：点击列表中客户记录后的「编辑」按钮，修改信息后保存。
4. **删除客户**：点击「删除」按钮，确认后删除（关联项目时系统会提示）。

**注意事项**：

- 客户名称不可重复。
- 已关联项目的客户删除前需先解除关联或转移项目。

### 2.8 工作量管理（v1.1 新增）

v1.1 版本新增工作量管理机制，项目经理作为工作量基准的设定者与进度审核人，贯穿「设定基准 → 审核累加 → 偏差监控 → 日报统计」全流程。

#### 2.8.1 设定工作量基准（创建/编辑任务）

**操作路径**：Web 端 → 进度任务 → 进度管理 → 新建/编辑任务

在任务创建或编辑表单中，新增以下工作量字段：

| 字段 | 字段名 | 说明 | 是否必填 |
|------|--------|------|---------|
| 计划工作量 | plannedWorkload | 该任务计划完成的工作量总数（数字） | ✅ |
| 工作量单位 | workloadUnit | 工作量计量单位 | ✅ |

可选工作量单位：条 / 个 / 台 / 芯 / 端口 / 机架 / 米 / 人天。

**操作步骤**：

1. 进入「进度管理」，点击「新建任务」或编辑已有任务。
2. 在常规字段（任务名称、计划起止时间、负责人等）之外，填写「计划工作量」与「工作量单位」。
3. 点击「保存」，工作量基准即生效，后续进度审核与偏差检测均以此为准。

> ⚠️ **计划工作量是偏差检测的基准**，请根据任务实际规模合理设定。设定过小会导致偏差误报，设定过大会掩盖进度滞后风险。
> 💡 任务进行中如需调整计划工作量，可在编辑任务时修改，但已累计的 actualWorkload 不会重置。

#### 2.8.2 审核进度自动累加工作量

**操作路径**：Web 端 → 进度任务 → 进度审核

工程师填报进度时需提交「本次完成工作量」（workloadHours）与「工作量描述」（workloadDescription）。PM 审核通过后，系统自动将本次工作量累加到任务的 actualWorkload 字段。

**操作步骤**：

1. 进入「进度审核」，查看待审核记录，列表新增展示「本次完成工作量」与「工作量单位」。
2. 点击进入审核详情，核对工程师提交的：
   - 本次完成工作量（workloadHours）
   - 工作量描述（workloadDescription）
   - 施工图片
3. 点击「审批通过」后，系统自动执行：
   - `actualWorkload = actualWorkload + workloadHours`
   - 任务进度按填报百分比更新
4. 驳回则不累加工作量，工程师需修改后重新提交。

> ⚠️ **审核通过前请核对本次完成工作量与工作量描述是否合理**，避免虚报。工作量一经累加不可自动回退，如需修正请联系系统管理员处理数据库。

#### 2.8.3 工作量统计卡片（工作台）

**操作路径**：Web 端 → 工作台（首页）

工作台新增**工作量统计卡片**（仅 admin / PM 可见），汇总展示 PM 管理项目范围内的工作量数据：

| 指标 | 说明 |
|------|------|
| 计划工作量总计 | 管理项目下所有进行中任务 plannedWorkload 之和 |
| 已完成工作量总计 | 管理项目下所有任务 actualWorkload 之和 |
| 剩余工作量 | 计划工作量总计 − 已完成工作量总计 |
| 工作量完成率 | 已完成工作量 / 计划工作量，以进度条形式展示 |

> 💡 通过完成率进度条可快速识别整体进度健康度，建议结合风险看板的偏差预警联动分析。

#### 2.8.4 风险看板工作量偏差预警

**操作路径**：Web 端 → 进度任务 → 风险预警看板

风险看板新增**工作量偏差预警**分区：

- **判定规则**：当任务满足「实际完成工作量 < 计划工作量 × 80%」且状态非「已完成」时，自动标记为**偏差任务**并纳入风险等级计算。
- **偏差任务列表**展示：任务名称、所属项目、计划工作量、已完成工作量、完成率、偏差率。
- 建议对偏差任务及时跟进：联系负责人核实进度、必要时调整计划工作量或重新分配资源。

> ⚠️ 若任务未设定计划工作量，则不参与偏差检测。请确保所有进行中任务均已设定工作量基准。

#### 2.8.5 日报导出工作量统计

**操作路径**：Web 端 → 数据分析 → 日报导出

日报导出 Excel 新增 3 列：

| 新增列 | 说明 |
|--------|------|
| 计划工作量 | 任务设定的 plannedWorkload |
| 已完成工作量 | 任务累计的 actualWorkload |
| 工作量完成率(%) | 已完成 / 计划 × 100% |

前端日报页面的任务进度表格同步新增对应列，便于在线预览。PM 仅可导出其管理项目范围内的日报。

## 三、常见任务流程图解

### 3.1 项目全流程管理

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  1. 创建项目  │ → │ 2. 分配团队  │ → │ 3. 创建任务  │ → │ 4. 工程师填报 │
│  PM 新建立项  │    │ 添加工程师   │    │ 拆分任务节点 │    │  提交进度    │
└─────────────┘    └─────────────┘    └─────────────┘    └──────┬──────┘
                                                                 │
┌─────────────┐    ┌─────────────┐    ┌─────────────┐           │
│ 7. 项目归档  │ ← │ 6. 进度更新  │ ← │ 5. PM 审核   │ ←─────────┘
│  完成后归档  │    │  任务进度推进 │    │ 通过/驳回    │
└─────────────┘    └─────────────┘    └─────────────┘
```

**说明**：项目经理贯穿全流程，重点把控**任务创建**与**进度审核**两个关键节点。

### 3.2 进度审核流程

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 1. 工程师提交 │ → │ 2. 通知 PM   │ → │ 3. PM 查看详情 │
│  填报进度+图片 │    │  站内/小程序  │    │  图片+工作量  │
└──────────────┘    └──────────────┘    └──────┬───────┘
                                                 │
                          ┌──────────────────────┴──────────────────────┐
                          │                                             │
                  ┌───────▼────────┐                            ┌───────▼────────┐
                  │  4a. 审核通过    │                            │  4b. 审核驳回    │
                  │  任务进度更新    │                            │  填写驳回意见    │
                  └───────┬────────┘                            └───────┬────────┘
                          │                                             │
                          │                              ┌──────────────▼──────────────┐
                          │                              │ 5. 工程师收到通知重新填报     │
                          │                              └──────────────┬──────────────┘
                          │                                             │
                          └─────────────────────────────────────────────┘
                                      （重新进入审核流程）
```

### 3.3 项目授权流程

```
┌────────────────┐    ┌────────────────┐    ┌────────────────┐
│ 1. 工程师申请   │ → │ 2. PM 审批     │ → │ 3. 授权生效     │
│ 选择目标项目    │    │ 查看申请理由    │    │ 工程师获得权限  │
│ 填写申请理由    │    │                │    │                │
└────────────────┘    └───────┬────────┘    └───────┬────────┘
                              │                     │
                   ┌──────────┴──────────┐          │
                   │                     │          │
            ┌──────▼──────┐       ┌──────▼──────┐   │
            │  授权（通过） │       │  拒绝（驳回）│   │
            └──────┬──────┘       └──────┬──────┘   │
                   │                     │          │
                   └─────────────────────┴──────────┘
                          （工程师收到结果通知）
```

**结果**：通过 → 工程师可在项目列表查看该授权项目；驳回 → 工程师可重新申请或放弃。

### 3.4 日报导出流程


## 四、注意事项与限制条件

### 4.1 进度审核

- ⚠️ **进度审核必须查看施工图片和工作量描述后才能通过**，未核实直接通过可能导致数据失真。
- 进度填报提交后，**需 PM 审核通过才会更新任务进度**，未审核前任务进度保持不变。
- 驳回必须填写意见，且一条记录只能审核一次。

### 4.2 项目删除与级联

- ⚠️ **项目删除会级联删除关联数据**，包括：任务、文档、项目团队、进度记录、授权记录等。
- 删除操作不可恢复，请谨慎执行，建议优先使用「归档」替代删除。

### 4.3 项目归档

- ⚠️ **项目归档后不可再编辑任务进度**，归档前请确认所有任务已完成或关闭。
- 归档后项目进入只读状态，可在「归档管理」中查询历史记录。

### 4.4 项目授权

- ⚠️ **同一项目不可重复授权给同一工程师**，系统自动校验。
- **项目授权转移后，原 PM 将失去该项目管理权**，请确认后再操作。
- 授权申请提交后由目标项目的 PM 审批，无可指定 PM 时联系系统管理员。

### 4.5 日报导出

- 📊 **日报导出 Excel 每个项目一个 Sheet**，便于按项目查看。
- 单次导出日期范围最长 31 天，超出需分次导出。
- 导出任务异步执行，完成后可在「导出记录」下载。

### 4.6 进度填报与审核联动

- 工程师填报后，PM 未审核前，该条记录状态为「待审核」，任务进度不变。
- PM 通过后，任务实际进度按填报值更新；驳回后，工程师需修改后重新提交。

## 五、问题排查与支持渠道

### 5.1 常见问题 FAQ

**Q1：为什么我看不到某个项目？**

A：项目可见范围分为三种：

| 可见范围 | 说明 |
|---------|------|
| `assignment` | 仅被授权的工程师可见，需 PM 审批授权 |
| `team` | 项目组成员可见 |
| `public` | 全员可见 |

如需查看 `assignment` 类型的项目，请通过「项目协作 → 授权申请」向该项目 PM 提交申请。

---

**Q2：审核通知未收到怎么办？**

A：排查步骤：
1. 检查「系统设置 → 个人信息」中手机号/邮箱是否正确。
2. 检查小程序「通知」列表是否有未读消息。
3. 确认浏览器是否允许系统通知（Web 端右上角铃铛图标）。
4. 若仍无通知，联系系统管理员检查通知服务状态。

---

**Q3：日报导出失败怎么办？**

A：可能原因与处理：
- **日期范围过大**：单次导出限制 31 天，请缩小范围后重试。
- **项目无数据**：所选日期范围内无进度数据，请更换日期或项目。
- **服务异常**：前往「导出记录」查看任务状态，若长时间失败请联系系统管理员。
- **浏览器拦截下载**：允许浏览器弹出窗口与下载权限。

---

**Q4：项目无法编辑或任务进度无法更新？**

A：检查项目是否已归档——**归档项目不可编辑**。如需修改，请联系系统管理员临时解档。

---

**Q5：授权申请被驳回如何处理？**

A：驳回意见会随通知发送，工程师可根据意见补充理由后重新提交申请。

### 5.2 数据权限说明

项目可见范围采用三级控制：

| 可见范围代码 | 可见范围名称 | 可见用户群体 |
|------------|------------|------------|
| `assignment` | 授权可见 | 被 PM 授权的工程师 |
| `team` | 团队可见 | 项目组成员 |
| `public` | 公开可见 | 全员可见 |

> 💡 项目经理可查看自己创建或被授权的全部项目，并对自有项目进行授权管理。

### 5.3 系统健康检查

如遇系统访问异常，可由系统管理员或运维人员通过以下接口检查服务状态：

```
GET http://服务器IP/api/actuator/health
```

正常返回示例：
```json
{
  "status": "UP"
}
```

- `UP`：服务正常
- `DOWN`：服务异常，请联系运维
- 若接口无法访问，可能为网络或服务未启动

### 5.4 联系系统管理员

如遇到以下情况，请联系**系统管理员**：

- 账号无法登录或密码遗忘（需重置）
- 需要新增/调整用户、角色、权限、岗位
- 项目需要解档或数据修复
- 系统功能异常或接口报错
- 需要撤销已生效的项目授权

**联系方式**：请通过企业内部通讯工具联系系统管理员，或提交工单至 IT 运维平台。
